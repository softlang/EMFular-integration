Editors and their Components

We provide completely wired editors, as well as all the necessary primitives for building a more tailored editor of your own. Our general assumption is that an editor consists of three parts:

  • the modeling canvas
  • the main editor bar, providing file-level functionality such as loading and saving models
  • the model-specific palette for any model specific operations like creating new model elements/li>

Complete Editors

Basic Editor

We provide a basic editor with the main editor bar and content projection slots for the graphical elements and the optional model specific palette.

The version below basically recreates the look of the complete tree editor further down the page. However, the tree model element component exposes a click binding for model elements, that we did not wire while the complete editor opens a details form.

Complete Tree Editor

Users who have no graphical representation of their own, can use this tree based editor. It already has the graphical details service wired in: when clicking on an element, a details form opens as a modal. If you then adapt any relationship on that, your choice dialogue for the other model element is the graphical tree details view you also see on the main canvas. This later interaction gave the service its name.

Building Blocks for Editors

If you want to control more than the basic editor allows you to, you might consider creating an own editor for the exported building blocks of our library.

Main Editor Bar

The editor bar is concerned with a fixed set of global model operations: creating, loading and saving models, undo and redo of edit operations, and downloading graphical representations. It needs two inputs: the model service, since it controls model editions and coordinates them with the history service, and an svg element, usually just the one from the drawing canvas, so that it can offer jpeg, png and svg downloads of it.
