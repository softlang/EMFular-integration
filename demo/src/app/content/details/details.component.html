Details

When modifying a single element with several properties, a details view (usually presented as a modal) can be helpful. We provide a generic element details component that displays all attributes and references of its metamodel. It relies on a details service, that manages details opening and choice dialogues for other elements, and an auxiliary reference details component.

The Reference Details Component

Every reference is a connection to other model elements. While there are singleton and list references, the modifications can be performed uniformly across both. We need a way to add (singleton set) another element, to remove it and to open its details in a new view to inspect the other element and determine if the relationship is intentional. While removal only requires a simple button, setting and adding must provide a way to choose another model element of fitting type. Depending on the domain, different visualizations or even simple radio buttons can offer appropriate handles. We leave that decision to the application developer and only enforce a small contract on the details service.

The Details Service

DetailsService defines the interaction required by the generic details component, and by anone who wants to open details. It provides three operations:

  • opening a details view for an element,
  • choosing a model element for a reference, and
  • choosing a new parent reference.

If you trigger the choice from a link reference, you can just choose another element and it will be clear over which relationships to connect. This is different for the definition of the parent, since a chosen element might have several tree-children references that could be meant. Hence, parent choice does not connect to another element, but to a specific container under such an element instead.

The Tree-Based Details Service

The library provides a default implementation that uses the same tree-based graphical representation that is used by the default model editor for both choice dialogues. Thus, users can select model elements in a representation they already know. An application could instead provide a list or radio-button based selection, or even a specific view per intended choice type. Which representation is appropriate depends on how the identity and relevant relationships of the application's model are best communicated to its users.

The Element Details Component

The element details component provides a generic view for editing a single model element. It contains a section for serializable attributes and a section for references. There is one additional section to re-organize the parent relationship in the tree-backbone.

Attributes can be edited using ordinary form controls. References and the parent relationship, however, require the user to select another model element. The details component therefore delegates these choices to a TreeDetailsService.
