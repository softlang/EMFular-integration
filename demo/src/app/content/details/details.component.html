Details

When modifying a single element with several properties, a details view (usually presented as a modal) can be helpful. We provide a generic element details component that displays all attributes and references of its metamodel. It relies on a details service, that manages details opening and choice dialogues for other elements, and an auxiliary reference details component.

The Reference Details Component

Every reference is a connection to other model elements. While there are singleton and list references, the modifications can be performed uniformly across both. We need a way to add (singleton set) another element, to remove it and to open its details in a new view to inspect the other element and determine if the relationship is intentional.

The Details Service

While removal only requires a simple button, setting and adding must provide a way to choose another model element of fitting type. Depending on the domain, different visualizations or even simple radio buttons can offer appropriate handles. To account for that, the contract of the DetailsService is deliberately simple and open.

If you trigger the choice from a link reference, you can just choose another element and it will be clear over which relationships to connect. This is different for the definition of the parent, since a chosen element might have several children-references that could be meant. The Element Details Component

The element details component provides a generic view for editing a single model element. It contains a section for serializable attributes and a section for references. There is one additional section to re-organize the parent relationship in the tree-backbone.

Attributes can be edited using ordinary form controls. References and the parent relationship, however, require the user to select another model element. The details component therefore delegates these choices to a TreeDetailsService.

The Tree Details Service

TreeDetailsService defines the interaction required by the generic details component. It provides three operations:

  • opening a details view for an element,
  • choosing a model element for a reference, and
  • choosing a new parent for an element in the tree backbone.

The service is deliberately separated from the details component. This allows an application to replace the generic details view or the way elements are selected without having to modify the generic editing logic.

The library provides a default implementation. Applications can provide their own implementation if a different presentation or selection mechanism is more appropriate for their model.

The default implementation uses the same tree-based graphical representation that is used by the model editor. Thus, users can select referenced or parent elements in a representation they already know. An application could instead provide, for example, a list or radio-button based selection. Which representation is appropriate depends on how the identity and relevant relationships of the application's model are best communicated to its users.

Details

When modifying a single element with several properties, a details view (usually as a modal) can be helpful. We offer a generic (element) details component that takes all attributes and all relationships of the metamodel into account. It uses a container details component to display the specific properties for each relationship.

The Element Details Component

We offer a functionality to re-organize the element within the tree-backbone by assigning a different parent element. There is also a dedicated section for all serializable attributes, and a final one for all references.

While the setting of attributes can happen by normal form handling, the choice of parent and other referenced elements might require a better fitting view. We offer a default, that provides the same tree based graphical model as the canvas has, so that users can choose another model element in the representation they know. Other approaches, even with simple radio buttons are possible but require a different understanding of what is sufficient to encode the model's identity.
